# Admit server-side Enterprise SDK skills, and generalize the version anchor to per-stack

The skill set was originally scoped to ArcGIS **client and authoring** surfaces — the JS SDK, Arcade, Experience Builder, the Python API, and docs lookup. Adding `arcgis-custom-data-feeds` deliberately widens that charter to include **server-side ArcGIS Enterprise SDK extension development**: a CDF provider is Node.js/Koop code that runs inside the Enterprise runtime, not client code. The trade-off — a broader, less homogeneous charter versus leaving a real and adjacent part of the ArcGIS developer stack uncovered — is accepted, because CDF is squarely "ArcGIS developer stack" and has no overlap with the existing five skills. The README charter sentence is widened to say so explicitly rather than letting the scope drift silently.

Admitting CDF forces a second decision. CDF does not track the ArcGIS Maps SDK for JavaScript version-matrix that the JS-family skills share — it tracks the ArcGIS Enterprise SDK CDF guide, a separate release train that fundamentally changed at Enterprise 12.0 (the `config` module retired; providers must be recompiled for 12.x). So the "single shared version anchor" premise of [ADR-0002](0002-version-facts-behind-a-live-anchor.md) no longer holds. We generalize the concept: the **version anchor is per-stack** — each version-needing skill points at the live Esri source that owns _its_ stack's versions. The JS SDK matrix stays the anchor shared by `arcade`, `js-sdk`, and `exb-widget`; `arcgis-custom-data-feeds` points at the Enterprise SDK CDF guide. The underlying principle from ADR-0002 — encode the discovery procedure and point at the live owner, never bake a matrix — is unchanged; only the assumption that there is exactly one owner is dropped. Two consequences follow and are handled where they belong, not as separate ADRs: `arcgis-docs-lookup` gains a fourth route for `developers.arcgis.com/enterprise-sdk` (per [ADR-0003](0003-arcgis-docs-lookup-owns-source-authority.md), it owns source authority), and the destructive-operation guard's glossary scope widens from "ArcGIS data" to "real data, including a CDF provider's upstream store" (the guard stays inlined per [ADR-0005](0005-inline-destructive-guard-per-skill.md)).
